# Default generated application template

This document describes the default Qornix Web application generated with:

```bash
./create_new_project.sh ../my_app
```

For the Schema Manager and Dynamic API showcase, use:

```bash
./create_new_project.sh ../my_api --with-dynamic-api
```


## Application preview

The default application generated by:

```bash
./create_new_project.sh ../my_app
```

opens with a clean landing page, status card, setup cards, useful file list and links to bundled docs.

![Default Qornix generated app](assets/qornix_app_snap.png)

For comparison, the Schema-driven Dynamic API application generated by:

```bash
./create_new_project.sh ../my_app --with-dynamic-api
```

starts with Schema Manager, Query Builder, Table Browser, API Playground, OpenAPI docs and demo database initialization controls.

![Qornix dynamic API generated app](assets/qornix_dynamyc_api_app_snap.png)

## Purpose

The default template is the recommended starting point for a custom C++ web service or web application that does not need the schema-driven Dynamic API on day one.

It includes:

- landing page at `/`;
- JSON health endpoint at `/health`;
- documentation hub at `/docs`;
- getting started, routing, configuration and deployment guides;
- static assets under `/static/{filename}`;
- bundled markdown docs rendered as in-app preview pages under `/docs/raw/{filename}`;
- portable deploy bundle under `build/deploy/<app>`.

## Generated layout

```text
my_app/
├── CMakeLists.txt
├── README.md
├── config.yaml
├── main.cpp
├── routes.h
├── app_paths.h

├── static/
├── doc/
├── route_extensions/
└── logs/
```

## Build

```bash
cd my_app
mkdir -p build
cd build
cmake ..
cmake --build .
```

## Run

Development executable:

```bash
cd build
./my_app
```

Portable bundle:

```bash
cd build/deploy/my_app
./my_app
```

Open:

```text
http://127.0.0.1:8008/
http://127.0.0.1:8008/docs
http://127.0.0.1:8008/health
```

## Deployment

Copy the entire bundle, not only the binary:

```bash
cp -R build/deploy/my_app /opt/my_app
cd /opt/my_app
./my_app
```

You can also run with an explicit root:

```bash
QORNIX_APP_ROOT=/opt/my_app /opt/my_app/my_app
```

The bundle contains app assets and documentation, but it does not bundle system shared libraries. Use `ldd ./my_app` to check runtime dependencies.

## Resource lookup

The generated app locates runtime assets in this order:

1. `QORNIX_APP_ROOT`
2. directory containing the executable
3. parent of the executable directory
4. current working directory
5. parent of current working directory
6. compile-time source directory fallback

This allows both development execution and portable deployment.

## Extending the app

Add handlers under `handlers/` and register routes in `routes.h`:

```cpp
server.add_route("/hello", std::make_shared<HelloHandler>());
```

See the generated page `/docs/routing` for a beginner-friendly guide.
