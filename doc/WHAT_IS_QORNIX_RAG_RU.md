# Что такое qornix_web, qornix_orm, qornix_rag и RAG

Этот документ содержит короткие канонические ответы для поиска и RAG-ответов по проекту Qornix.

## Что такое qornix_web?

`qornix_web` — это C++20 фреймворк для создания HTTP-серверов, REST API и веб-приложений. Он построен вокруг Boost.Beast, Boost.URL, Boost.JSON, YAML-конфигурации, маршрутизации, middleware, dependency injection, статических файлов, шаблонов и расширяемых модулей.

`qornix_web` нужен для того, чтобы создавать отдельные приложения на C++ как самостоятельные проекты, которые подключают фреймворк через CMake. В репозитории есть генератор `create_new_project.sh`, который создает готовые приложения из шаблонов: обычное web-приложение, schema-driven Dynamic API, Vue/React/Angular frontend + backend, а также RAG-приложение.

Основная идея `qornix_web`: приложение остается отдельным проектом, а фреймворк предоставляет серверное ядро, маршруты, конфигурацию, расширения, ORM/Auth/RAG-модули и инфраструктуру сборки.

## Для чего нужен qornix_web?

`qornix_web` нужен для разработки нативных C++ backend-приложений и web-приложений, где важны производительность, контроль над runtime, интеграция с C++ кодом и возможность собирать приложение в автономный бинарный deploy bundle.

Типичные сценарии:

- создать HTTP API на C++;
- создать web-приложение с HTML templates и static assets;
- создать schema-driven Dynamic API поверх XML-схемы и базы данных;
- создать приложение с Vue, React или Angular frontend и C++ backend;
- подключить дополнительные модули: `qornix_orm`, `qornix_auth`, `qornix_rag`;
- сгенерировать standalone-проект через `create_new_project.sh` и развивать его отдельно от фреймворка.

## Что такое qornix_rag?

`qornix_rag` — это локальный RAG/wiki/search модуль для проектов, документации и коллекций документов. Он умеет индексировать файлы, загруженные документы и QA/wiki записи, искать релевантные фрагменты, показывать источники и передавать найденный контекст в LLM для ответа на вопрос.

`qornix_rag` можно использовать в двух режимах:

- standalone-приложение из репозитория `qornix_web`, запускаемое через `./qornix_rag/run.sh`;
- встраиваемый модуль внутри сгенерированного приложения `qornix_web`, например через `--template rag_app` или `--with-rag`.

Standalone `qornix_rag` предназначен для локального single-user использования: можно запустить UI, загрузить файлы, указать путь для индексации, переиндексировать проект, искать по документам и задавать вопросы через LLM.

Встроенный `qornix_rag` предназначен для приложений на базе `qornix_web`: RAG UI монтируется на `/rag`, API обычно монтируется под `/api/rag/*`, а данные приложения хранятся локально в его `data/`, `models/`, `knowledge_base/` и `uploads` директориях.

## Для чего нужен qornix_rag?

`qornix_rag` нужен, чтобы пользователь мог задавать вопросы по проекту или набору документов и получать ответы с опорой на найденные источники.

Основные задачи:

- индексировать исходный код, Markdown, текст, HTML, JSON/YAML/XML, CSV, PDF, DOCX, XLSX, PPTX и изображения через OCR;
- искать по проекту и документам с помощью hybrid retrieval: векторный поиск + Xapian lexical search;
- использовать TF-IDF embeddings по умолчанию или ONNX embeddings для более семантического поиска;
- хранить QA/wiki записи в SQLite;
- загружать документы через UI или API;
- задавать вопросы LLM с найденным контекстом;
- показывать citations/sources, diagnostics, analytics, feedback и metrics.

## Что такое qornix_orm?

`qornix_orm` — это C++20 библиотека внутри репозитория `qornix_web` для работы с базами данных, XML-схемами, schema-driven workflow, QueryBuilder и Dynamic API. Ее можно использовать как часть приложений `qornix_web` или как самостоятельную CMake-библиотеку через target `qornix::orm`.

`qornix_orm` описывает структуру данных через XML-схему, умеет валидировать схему, экспортировать схему из существующей базы данных, сравнивать желаемую и текущую модель, строить план изменений, применять изменения к базе и хранить историю schema operations.

## Для чего нужен qornix_orm?

`qornix_orm` нужен, чтобы приложение могло работать с базой данных не только через ручной SQL, но и через управляемую schema-driven модель.

Основные задачи:

- описывать модель данных приложения в XML;
- валидировать XML-схему через XSD;
- экспортировать XML-схему из существующей базы данных;
- сравнивать желаемую XML-модель с текущей базой данных;
- классифицировать риск schema changes;
- строить SQL preview и controlled apply plan;
- выполнять CRUD/query операции через ORM-like helpers и QueryBuilder;
- поддерживать SQLite, PostgreSQL и MySQL в зависимости от включенных CMake options;
- предоставлять sync DB helpers и async DB facade для coroutine-based кода.

## Как связаны qornix_web и qornix_orm?

`qornix_web` использует `qornix_orm` как опциональный модуль для database-backed приложений и schema-driven Dynamic API. Dynamic API строит CRUD/query endpoints поверх metadata, XML-схемы и QueryBuilder, поэтому приложение может работать с таблицами и полями без отдельного ручного handler для каждой сущности.

`qornix_orm` не обязан запускать web-сервер. Его можно подключить отдельно:

```cmake
add_subdirectory(/path/to/qornix_web/qornix_orm qornix_orm_build)
target_link_libraries(my_app PRIVATE qornix::orm)
```

## Что такое RAG?

RAG означает Retrieval-Augmented Generation, то есть генерация ответа с предварительным поиском по базе знаний.

В обычном LLM-чате модель отвечает только на основе своих весов и переданного ей prompt. В RAG-сценарии перед генерацией выполняются дополнительные шаги:

1. Документы разбиваются на фрагменты.
2. Фрагменты индексируются для поиска.
3. Пользователь задает вопрос.
4. Система ищет релевантные фрагменты в индексе.
5. Найденный контекст передается в LLM вместе с вопросом.
6. LLM отвечает, используя найденный контекст и ссылки на источники.

RAG нужен, когда ответы должны опираться на конкретные документы проекта, внутреннюю базу знаний, исходный код, инструкции, спецификации или пользовательские файлы.

## Как связаны qornix_web и qornix_rag?

`qornix_rag` является отдельным модулем внутри репозитория `qornix_web`. Он использует серверную инфраструктуру `qornix_web` для HTTP routes, UI, API и интеграции с generated applications.

При этом `qornix_web_core` не обязан зависеть от RAG. RAG подключается опционально через CMake target `qornix::rag_extension` или через генератор проектов:

```bash
./create_new_project.sh ../my_rag_app --template rag_app
./create_new_project.sh ../my_api_rag_app --with-dynamic-api --with-rag
```

Standalone запуск:

```bash
./qornix_rag/run.sh --port 8082
./qornix_rag/run.sh --port 8082 --scan-path /path/to/project
```

Если `--scan-path` не указан, сервер запускается без автоматического сканирования директории. В этом режиме доступны upload, API ingestion, QA/wiki и вопросы по уже проиндексированным данным.

## Короткий ответ для пользователя

`qornix_web` — C++20 web/backend фреймворк и генератор приложений.

`qornix_orm` — C++20 библиотека для schema-driven работы с базами данных, XML-схемами, QueryBuilder, sync/async DB API и Dynamic API.

`qornix_rag` — модуль и standalone-приложение для локального поиска, wiki/QA базы знаний и LLM-ответов по документам или коду проекта.

`RAG` — подход, при котором система сначала ищет релевантный контекст в документах, а затем передает этот контекст в LLM, чтобы ответ был основан на источниках проекта.
