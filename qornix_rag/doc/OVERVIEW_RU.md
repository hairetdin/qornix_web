# Обзор qornix_rag

Этот документ содержит короткие прямые ответы для пользователей, которые индексируют только директорию `qornix_rag/`.

## Что такое qornix_rag?

`qornix_rag` — это локальный RAG/wiki/search модуль для проектов, документации и коллекций документов. Он индексирует файлы, загруженные документы и QA/wiki записи, ищет релевантные фрагменты, показывает источники и передает найденный контекст в LLM для ответа на вопрос.

`qornix_rag` можно запускать как standalone-приложение через `./qornix_rag/run.sh` или встраивать в generated-приложения `qornix_web` через `--template rag_app` или `--with-rag`.

## Для чего нужен qornix_rag?

`qornix_rag` нужен, чтобы пользователь мог задавать вопросы по проекту, документации, базе знаний или загруженным файлам и получать ответы, основанные на найденных источниках.

Он решает задачи локального поиска, базы знаний, загрузки документов, hybrid retrieval, генерации ответов через LLM, цитирования источников, диагностики качества поиска и хранения QA/wiki записей.

## Что такое RAG?

RAG означает Retrieval-Augmented Generation. Это подход, при котором система сначала ищет релевантный контекст в документах, а затем передает этот контекст в LLM для генерации ответа.

В `qornix_rag` RAG-процесс выглядит так:

1. Файлы или QA/wiki записи попадают в систему.
2. Документы разбиваются на фрагменты.
3. Фрагменты индексируются для lexical и vector search.
4. Пользователь задает вопрос.
5. Система ищет релевантные источники.
6. LLM получает вопрос и найденный контекст.
7. Пользователь получает ответ со ссылками на источники.

## Как работает поиск в qornix_rag?

`qornix_rag` использует hybrid retrieval: сочетает lexical search через Xapian и vector search через embeddings. По умолчанию доступен легкий TF-IDF backend. Для более семантического поиска можно включить ONNX embeddings и совместимую embedding model.

Индексация директории необязательна. Если `indexing.scan_path` или `--scan-path` не указан, сервер стартует без автоматического сканирования, но остаются доступны upload, API ingestion, QA/wiki и вопросы по уже проиндексированным данным.

## Как qornix_rag связан с qornix_web?

`qornix_rag` находится внутри репозитория `qornix_web`, но является отдельным reusable-модулем. `qornix_web` предоставляет HTTP/UI/API инфраструктуру, а `qornix_rag` предоставляет RAG-функциональность.

В standalone-режиме `qornix_rag` запускается из репозитория:

```bash
./qornix_rag/run.sh --port 8082
./qornix_rag/run.sh --port 8082 --scan-path /path/to/project
```

В generated-приложении RAG подключается как модуль:

```bash
./create_new_project.sh ../my_rag_app --template rag_app
./create_new_project.sh ../my_api_rag_app --with-dynamic-api --with-rag
```

## Короткий ответ

`qornix_rag` — это локальный модуль поиска, базы знаний и LLM-ответов по документам проекта. Он нужен, чтобы индексировать код и документы, находить релевантные источники и отвечать на вопросы пользователя с опорой на контекст проекта.
